# Decisions

Only decisions that constrain how new work should be done.

## Stack

- **Next.js 16 App Router + React 19 + TypeScript.** Editor route is `"use client"` and loaded with `dynamic(..., { ssr: false })` so PlayCanvas, MapLibre, and Zustand never run on the server.
- **Zustand** for editor state, not React Context and not a single mega-store. Live stores are the active scene; `useScenesStore` is the project record.
- **react-hook-form + Zod** for settings/hotspot forms. Store writes stay in the form hooks.
- **@xyflow/react** for action graphs. Domain graph stays `{ nodes, edges }`; `flow-adapter.ts` is the only UI mapping.
- **PlayCanvas** for model/image scenes; **MapLibre** for geo. Scene type picks the engine — do not render both as the interactive viewport.
- **Tailwind 4 + custom editor tokens** (`editor-theme.css`). shadcn (`components/ui`) for primitives; editor chrome in `app/editor/_components/ui`.
- **Editor toasts** are custom (`lib/editor/toast.ts` + `EditorToaster`), not sonner. Mount the toaster inside `.editor-root` so glass tokens apply; keep them bottom-right so they don’t cover the center viewport menu.
- **Editor UI and toast stores outlive the route.** `EditorProjectLoader` calls `resetTransientUI()` and `toast.dismiss()` on unmount, so modals and toasts don't carry over to the next visit. New overlay flags in `ui-store` belong in `TRANSIENT_UI`.
- **Delete confirmation** is `confirmDelete` / `confirmDeleteMany` (`lib/editor/confirm.ts`), rendered by `ConfirmDialogHost` inside `.editor-root`. Call it before a destructive editor action that cannot be undone. Deletes that are recorded in history (action canvas nodes, connections, fences) skip the dialog and show an Undo toast instead. Do not add a one-off confirm dialog or `window.confirm`.
- **Devcontainer / WSL:** `WATCHPACK_POLLING` and webpack `watchOptions.poll` so file watching works. Poll **source only** (`ignored`: `node_modules`, `.next`, `worker`) — polling the PlayCanvas tree every second stalls the event loop and drops `localhost:3000`. Dev heap is `NODE_OPTIONS=--max-old-space-size=8192` because webpack + PlayCanvas sits near Node’s ~2 GB default. Keep that if changing `dev` or `next.config.ts`.
- **Neon Lakebase Postgres + Managed Better Auth** for identity and tenancy. Org is the tenant boundary (`neon_auth.organization` / `member`). Do not add parallel `users` / `organizations` tables in `public`. Auth DDL is Neon-managed; Drizzle only introspects `neon_auth`.
- **API gateway:** Cloudflare Worker (`worker/`, scaffolded with `cf`). Next.js is the UI, not the auth or data API. The browser calls same-origin `/gateway/*`, and Next proxies that to the Worker. The Worker proxies `/auth` to Neon Auth, `/data` to the Neon Data API with the user JWT, and `/fn` to a Neon Function when one exists. Drizzle stays for migrations and future Function code. Do not put `DATABASE_URL` or Neon URLs in the browser.
- **RLS** is the database authorization layer for Data API reads and writes. Public product tables need `ENABLE ROW LEVEL SECURITY` (and usually `FORCE`) plus policies in the Drizzle migration before the Data API role can read them. Do not expose `neon_auth` through `/data`.
- **Auth UI:** Email/password via the Neon Auth browser client. Sign-up stays closed (UI + Neon `disable-sign-up`) and email verification stays off until product UI is ready. Post-login landing is `/projects` (studio dashboard). `/orgs` is a legacy redirect only.
- **Active org reads bypass the auth client cache.** `authClient.getSession()` is served from the Neon adapter's in-memory session cache, which `organization.setActive` does not invalidate. Read `activeOrganizationId` with a direct `GET /gateway/auth/get-session?disableCookieCache=true` (`getActiveOrganizationId` in `lib/projects/orgs.ts`). Opening a project makes its org active.
- **Product tables:** `project_folders` and `projects` in `public`, migrated via Drizzle (`lib/db/app-schema.ts`). RLS uses `public.is_org_member(organization_id)` (SECURITY DEFINER over `neon_auth.member`) so the Data API `authenticated` role does not need grants on `neon_auth`. SQL reads the user via `public.current_user_id()` (claims GUC first), never `auth.user_id()` directly: the first `auth.*` call in a backend loads `pg_session_jwt`, and if that happens inside a SECURITY DEFINER function the request's claims are dropped and RLS hides everything (migration `0005`). Browser CRUD uses `/gateway/data/*` + TanStack Query (`lib/projects/`). Do not put Auth tables in app migrations.
- **Studio UI (`/projects`)** is client-only (`dynamic(..., { ssr: false })`) and uses its own tokens in `app/projects/projects-theme.css`. Menus and dialogs go through `StudioMenu*` / `StudioDialog` (Radix + CSS keyframes). They portal outside `.studio-root`, so they carry `.studio-portal` + `studioFontClass`. Do not use the shadcn `DropdownMenu` there, because its bare `border` picks up `currentColor`. Menus are non-modal so menu items can open dialogs.
- **Studio UI primitives:** avatars are always `Avatar` (`avatar.tsx`: flat color seeded from the name, no gradients; `shape="rounded"` + `src` for org logos). Role pills are always `RoleBadge` (`role-badge.tsx`; owner amber, admin teal, other neutral; colors in `.studio-role`). Menu spacing is a rule, not per-menu padding: items are 2px apart and rows with an avatar or second text line use `rich` on `StudioMenuItem` / `StudioMenuRadioItem` (48px rows, 4px apart).
- **Object files (later):** Cloudflare R2, not Neon Object Storage. **Queues (later):** Cloudflare. Rate limits for auth writes and `/data` live on the Worker.

## Scene model

- **`Scene.type` is immutable** after create. Camera mode, subject loader, settings sections, and outliner tabs come from `scene-types/registry.ts`, not ad-hoc checks.
- **Snapshot on switch.** Outgoing live stores are written back onto the `Scene`; incoming scene hydrates the live stores. New per-scene data must be cloned in `snapshotCurrentIntoScene` and restored in `switchScene`.
- **New scenes** copy the primary scene’s settings/environment but start with empty `resetPosition` and `customMenuButtons`.
- **At least one scene** is required. Deleting a geo scene referenced by a `geoReference` marks that reference `invalid`.
- **Scene Explorer enable is project-wide** (`general-settings-store.sceneExplorerEnabled`), unlike per-scene `legendEnabled`. Optional drawer titles and edge insets follow that split (`sceneExplorerTitle` / `sceneExplorerInset`, `legendTitle` / `legendInset`); a blank title keeps “Scene explorer” / “Legend”, and inset defaults off. Description and thumbnail live on `Scene`, not `EditorSettings`.

## Actions

- **Registry-driven nodes.** Add a type to `hotspot-action.ts`, defaults in `create-action-graph.ts`, `validate`/`run` in `actions/registry.ts`, and a canvas component in `action-node-registry.tsx`. Gate with `sceneTypes` when the node is engine-specific.
- **Owner allow-lists** (`action-owners.ts`) decide which nodes appear on hotspot vs start vs menu / Action button graphs. Open Modal is on hotspot, Scene Start, Legend, menu and Action button graphs; off hotspot lanes it must pick a scene dialog. App Start cannot use it (dialogs are per scene). Animation is on hotspot, Scene Start, Legend, menu, and Action button graphs — not App Start.
- **Synthetic owner ids** (`−1`, `−2`, `−4`, Action buttons `−5000…−9999`, `≤ −10000`) must never collide with hotspot ids, spawn-click (`−3`), or spawned ids (`SPAWNED_HOTSPOT_ID_BASE = 1_000_000`).
- **Preview overlays, not authored edits**, for Enable/Disable, appearance changes, mesh highlight, spawned pins, and GLB animation playback. Leaving Preview resets them (including bind pose) and stops Subscribe polls / Post Message listeners / HTTP cache. HTTP Request, Subscribe, and Post Message playback keep the live JSON in that session cache. Do not write `lastResponseJson` or `lastPayloadJson` from `run`; the node Test action stores the sample used for field tokens. For Each reads the upstream node's cache before any other node's saved sample.
- **Editor pose preview** is session chrome (`editor-anim-preview-store`), not snapshotted onto the Scene. The viewport transport plays/scrubs named GLB clips in Select/Add so authors can place hotspots against a posed mesh. It does not run the action graph. Graph Animation stays Preview-only. Enter/leave Preview, scene switch, and subject replace restore bind pose and idle the slider.
- **Post Message receive tester** is editor-session state (`preview-post-message-test-store`), not `node.data`. It injects `{ event, data }` to the same window; do not rewrite send targets or fall back to `self` for outgoing sends. Do not show this HUD in a future viewer.
- **`run` returning `"stop"`** ends the primary walk (Open Modal branches, Subscribe poll, receive-mode Post Message, Switch/For Each tails, cancelled Animation playback).
- **Legend trigger** is first-class like Scene Start: a scene-scoped graph (`legendActions`) whose canvas lane appears only while Enable legend is on. One source handle per category (plus All). `selectLegendFilterCategory` walks the matching handle; leaving Preview must not fire it. Keep the graph when legend is turned off so re-enabling restores wiring.
- **Compressed GLB:** Draco and KTX2 / Basis use PlayCanvas' own support with decoders self-hosted in `public/decoders/` (pinned copies, see its README), configured once by `configureModelDecoders`. PlayCanvas has no meshopt support, so `decodeMeshoptGlb` (`meshoptimizer` package) rewrites meshopt GLBs into plain GLBs before load. The stored asset stays the original compressed file. Code that reads vertex data must handle quantized (`KHR_mesh_quantization`) positions, as `subject-surface.ts` does.
- **Mesh click is a hotspot, not a new system:** `Hotspot.meshId` binds a hotspot to a catalog mesh (path-based id from `collectModelMeshes`). It reuses the hotspot actions, blocks, Open Modal, legend, persistence and canvas lane. The differences:
  - It has no marker. The hidden visual tracks the live mesh centre so anchors and labels still work.
  - Picking is a CPU raycast (`engine/mesh-raycaster.ts`), run only on pointer events (hover coalesced to one per animation frame) and only while the scene has mesh-bound hotspots:
    - An AABB broad phase over every visible model mesh instance.
    - Then exact ray/triangle tests front to back in mesh-local space. These stop once the next box starts beyond the closest surface found, so non-clickable meshes still occlude.
    - Triangles are read once per `Mesh` (`engine/mesh-geometry.ts`, shared with the surface sampler).
    - Don't use `pc.Picker` for hover: each `prepare()` re-renders the whole World layer.
  - Markers win.
  - Hover / active highlights are drawn under Highlight Mesh node paint (`effectiveMeshHighlights`). Hover is tint-only; only the active mesh gets an outline.
  - `mesh-highlight-manager.sync` is incremental and caches tinted clones. Its `OutlineRenderer` is created once and its camera disabled when idle. Never create or destroy it per change: it adds a scene camera and render targets.
  - Gated by `meshClick` in the scene-type registry. Keep one hotspot per mesh (no Duplicate).
  - Missing meshes are reported (`useMeshBinding`), never auto-cleared.
  - UI reads mesh centres through `model-mesh-queries.ts`, not PlayCanvas.
- **Scene dialogs reuse blocks + Open Modal, not a new system.** A `SceneDialog` (`Scene.dialogs`: title, header image, `HotspotBlock[]`, optional modal / drawer + size overrides) is shown by Open Modal with `dialogId`. Decisions:
  - Per scene, stored on the `Scene` record (like `startActions`), so no snapshot / hydrate store; old saves default to `[]` (no schema bump).
  - **One Preview dialog slot.** A scene dialog and the hotspot dialog share `previewModalOpen`; opening one replaces the other and fires its onClose. No stacking in v1.
  - Scene dialogs never move the camera and have no prev/next. Infobox (scene default) falls back to modal: there is no anchor.
  - Action buttons inside a dialog are content-button owners like hotspot ones; their lanes sit on the Scene Actions canvas, and every content-button lookup (`content-buttons.ts`, `useOwnedActionNode`, `setOwnedActionGraph`) also walks dialogs. Duplicating a dialog remints them.
  - **Show once per session** (`showOncePerSession`) is tracked in `dialogs/dialog-session.ts` (module-level set, not authored), reset on entering / leaving Preview. A skipped dialog runs its Open Modal onClose branch (not onOpen), as if it was shown and dismissed, so follow-up chains (fly to start, etc.) still run. A future viewer should back it with `sessionStorage`.
  - Deleting a dialog uses the Undo toast (history scope `dialogs:<sceneId>`), not a confirm; Open Modal nodes that pointed at it show "Dialog no longer exists", like Go To Scene.
- **Action fences are scene-wide** so hotspot and scene canvases share the same frames.
- **Action canvas lanes have a persisted origin** (`HotspotActionGraph.laneY`); node positions are relative to it and fences are absolute. Lanes are never placed by list position: an owner without `laneY` (new hotspot, menu button, button block, legend turned on) is placed below all existing lanes and fences (`resolveLaneOrigins` in `lib/editor/actions/action-lanes.ts`), and the canvas saves that origin. Older saves are frozen to their old 220px-per-lane layout in `hydrateProject`. Duplicated hotspots / reminted button blocks drop `laneY` so they get a fresh lane.
- **Animation clips by name.** The Animation node plays named glTF clips from the loaded GLB, not Blender frame ranges. Optional start/end seconds trim that clip (defaults to the clip’s own range). `run` waits until the window completes, then holds that pose; interrupt / leave Preview / subject replace cancels the wait (`"stop"`).
  - **Loops are a node mode, not a subject setting.** Loop / Ping-pong start a repeating window and return immediately, so a Scene Start graph covers the "loop on scene start" case and hotspots can start loops too. Clips stay assigned non-looping; `model-animation.ts` wraps the layer time on a rAF ticker so trim and inverse still apply. One base layer means one clip at a time: the engine remembers a single `activeLoop`, a newer loop replaces it, and a Play once clip interrupts it and restarts it on completion when `resumeAfterInterrupt` is on. Stop loop, reset (enter/leave Preview, scene switch), unbind, and the editor transport clear it.
  - Editor Select/Add can scrub the same clips via the viewport transport without waiting or continuing the graph.
- **Wait** pauses the primary walk for `durationSeconds` (0–300, default 1) then continues. Available on every owner including App Start. Leave Preview or scene switch cancels in-flight waits (`"stop"`).

- **Action graphs are acyclic.** `connect` and the canvas `isValidConnection` reject any edge that would close a loop (`wouldCreateCycle`, all branches). Legacy saves with a cycle are contained at run time: `chainFrom` never re-enters its start node, and `runActionNodeList` tracks `ctx.runPath` (node ids executing up the call stack) and stops with a toast when a node re-enters itself.
- **A run owns its state; nothing global spans an `await`.** The For Each item travels in `ActionRunContext.itemScope` (each iteration passes `{ ...ctx, itemScope }` to the tail; spawned-hotspot click / close runs set it from the spawn entry). The `interpolate*` helpers still read an ambient scope, but `runActionNodeList` only sets it for the synchronous start of a node's `validate` / `run` (`withItemScope`), so concurrent runs (click, Subscribe poll, Post Message) cannot see each other's item. A node that reads fields after an `await` must re-enter the scope with `withItemScope(ctx.itemScope, …)` (For Each and Switch do). Runs are also cancellable: each remembers `ctx.runGeneration`, and `cancelPendingWaits` (leaving / entering Preview, scene switch, Scene Start) bumps the generation, so the run stops before its next node and For Each stops between items. Event-driven entries (Post Message receive, Subscribe payload) start a new run with `freshRunContext`, because App Start listeners outlive scene switches.
- **HTTP Request / Subscribe fetches are bounded and anonymous** (`executeHttpRequest`, the single path for both nodes and their Test buttons). 15 s timeout (also covers reading the body), 5 MB response cap (declared length and streamed), `credentials: "omit"` so the signed-in session cookie is never sent to a project's URL, and `sameOriginRequestError`: requests to this app's own origin may only be GET / HEAD and never under `/gateway/`. The same check runs in `validateHttpRequestData`, so the node shows the error before Preview. Requests started by a running chain (`cancelWithRun`) are tracked in `request-cancel.ts` and aborted by `cancelPendingWaits`; a response that arrives after the run was cancelled is ignored. Nodes cannot attach the session on purpose: a project that needs an authenticated API must use an explicit `Authorization` header.
- **Post Message receive only trusts listed senders.** The receive node has `allowedOrigins` (space/comma separated). Empty accepts only the page itself (the Preview tester); `*` accepts any sender explicitly. Older saves omit the field and are strict. A viewer embedded in someone's site needs that site's origin listed.
- **Legend categories change through `setLegendCategories`** (`lib/editor/state/legend-categories.ts`): removing one clears it from the active scene's hotspots and from Spawn Hotspot templates in that scene's graphs and menu buttons. Do not call `setSettings({ legendCategories })` directly.
- **Hand-offs between hotspots are loop-guarded.** `ActionRunContext.hotspotChain` lists the hotspots whose actions led to this run (a fresh click starts at its own hotspot; Open Modal remembers the chain on its close handler; Go To Hotspot with "run target actions" extends it). A hand-off back into a hotspot already in the chain is refused with a toast, so `onClose -> Go To Hotspot (self)` and A <-> B ping-pong cannot re-open dialogs forever.
- **Scene transitions die with Preview.** The transition token lives in `scene-transition-chain.ts`; toggling Preview in either direction cancels it and drops the splash, so a fade in flight never switches scenes in Select mode.
- **Start-graph scene hops are loop-guarded.** Go To Scene run from App Start / Scene Start is "automatic": `scene-transition-chain.ts` refuses a hop back into a scene already visited by the chain (hops closer than 5 s apart; slower, deliberate Wait-driven slideshows are fine). A user-initiated transition or toggling Preview resets the chain.
- **Copied action graphs get fresh ids.** Duplicated hotspots, their action-button blocks, and spawned hotspots use `remintActionGraph` (new node + edge ids; `{{path@nodeId}}` tokens follow). Owner lookup, HTTP caches and Spawn pass keys are keyed by node id, so copies must not share them. Plain `cloneActionGraph` keeps ids and is for same-owner snapshots.

## Geo and coordinates

- **Canonical local frame is ENU:** +X east, +Y north, +Z up (meters). Control points are source of truth; the 4×4 is derived.
- **3-point alignment for models, 2-point for images.** Geo scenes are not alignment targets.
- **Spawn lat/lon on PlayCanvas** goes through `geoToScene` only when `geoReference.status === "aligned"`.
- **Spawn Y on 3D scenes** (gated by `spawnSurfacePlacement` in the scene-type registry, model only): API lat/lon carries no usable height, so only the converted x / z are kept and Y is the topmost subject surface there, so pins never sit inside buildings of different heights. The query (`engine/subject-surface.ts`) projects triangles onto XZ and interpolates Y; it keeps a per-mesh-instance world-space copy plus an XZ grid, rebuilt only when that mesh's world matrix changes. Action code reaches it through the `bindSubjectSurface` binding set by `model-manager`, never engine instances. Per-node template fields: `yPlacement` (`surface` default / `explicit`), `surfaceOffset` (default 0.3, same lift as Add mode), `surfaceFallback` (`ground` default / `subjectTop` / `skip`) for no hit. Explicit Y is in scene units, no offset. Meshes disabled in Preview are ignored; skinned/animated meshes are sampled in bind pose.

## Rendering details

- PlayCanvas uses `FILLMODE_NONE` + manual resize (`viewport-resize.ts`) so CSS owns canvas size.
- Backbuffer pixel ratio is 1 (`MAX_PIXEL_RATIO` in `viewport-resize.ts`): retina screens render at CSS size with MSAA, no adaptive resolution. The canvas is opaque (`alpha: false`). SSAO runs at half resolution (`ssao.scale = 0.5`).
- The PlayCanvas loop skips work while the viewport is hidden: a backdrop dialog covers it (`isViewportCovered` in `use-playcanvas-editor.ts`: actions, asset library, scenes, publish) or the canvas is off-screen (IntersectionObserver). The last frame stays behind the backdrop; closing redraws. Hotspot pulse / halo frames stop while the window is unfocused. Add new full-cover dialogs to `isViewportCovered`.
- Viewport thumbnails call `app.render()` then `toDataURL` in the same turn; do not leave `preserveDrawingBuffer` on.
- MapLibre workers are copied into `public/` on `postinstall` and served with a JavaScript `Content-Type` (module workers).
- **On-demand rendering.** `autoRender` is always off. `onUpdate` in `use-playcanvas-editor.ts` sets `renderNextFrame` only when the camera moved, a clip is playing, a store the scene reads changed, or something called `requestViewportRender` (`engine/viewport-invalidate.ts`). Hotspot pulse / halo animations redraw at most 30 fps. Engine code that changes the scene outside a store update (async textures, drag, clip pose, resize) must call `requestViewportRender`, or the change stays invisible until the next redraw. Do not subscribe redraws to fields `onUpdate` itself writes (`fps`, label / info-box anchors): that loops.
- The WebGL context uses `powerPreference: "default"`. Do not switch back to `"high-performance"`: it wakes the discrete GPU on dual-GPU laptops.
- On geo scenes the PlayCanvas layer stays mounted but hidden; `onUpdate` returns early so nothing is drawn.
- Model-scene key-light shadows are 4096² with one cascade. `SHADOWUPDATE_REALTIME` only while a clip is playing; otherwise `SHADOWUPDATE_THISFRAME` (frozen map). Pause, scrub, and reset recapture once via `requestViewportRender({ shadows: true })`. Recapture after light or model-transform changes. Do not refit `shadowDistance` while frozen so orbiting stays cheap.
- 3D hotspot drag moves the live entity only; the authored position is committed on pointerup.
- `hotspot-manager.update` runs every tick, so it only writes what changed: marker scale is set when it differs, billboards re-orient once per camera turn, and the halo is disabled unless selected / open. Animated fades (pulse ring, halo) set the `material_opacity` mesh-instance parameter, never `material.opacity` + `update()`. Helpers it calls per hotspot (`listPreviewHotspots`, `resolveHotspotAppearance`, `isPreviewHotspotEnabled`, spawned `list()`) are memoized by input identity; keep them allocation-free.

## Hotspot content blocks

- **Registry-driven blocks.** Add a type to `hotspot-block.ts`, defaults in `create-block.ts`, non-UI meta in `blocks/registry.ts`, and Editor / Preview / `collapsedPreview` in `block-registry.tsx`. Do not add one-off `if (type === …)` checks in the blocks tab.
- **Image blocks** store slides in `items[]` (`asset:<id>` or a URL / `{{token}}`) with an optional per-slide caption. Caption and URL fields persist tokens immediately (same insert control as other blocks). Preview and Spawn interpolate both `src` and `caption`. One slide is a still; two or more render a Preview carousel (buttons only — do not bind ArrowLeft/Right, those switch hotspots in the marker dialog).
- **Video blocks** accept YouTube or Vimeo URLs only. Parse to a privacy-aware embed (`youtube-nocookie` / `player.vimeo.com`). No file upload or direct `.mp4`. Token URLs are interpolated, then checked as YouTube/Vimeo (editor hint + Preview iframe).
- **Block validation** lives in `validateBlock` (`lib/editor/blocks/validate-block.ts`), one switch over block types, and only drives the card warning. It never blocks saving or Preview. Values with `{{tokens}}` are only checked for being non-empty.
- **Block delete has no confirmation** (unlike other editor deletes): blocks are cheap to recreate and Undo restores them. **Duplicate** goes through `duplicateBlock`, which gives the copy a new block id, new image slide ids, and for Action buttons a reminted owner (`cloneButtonBlock(…, true)`).
- **File blocks** store `src` (`asset:<id>` or an http(s) URL / `{{token}}`) and an optional title. Library files use asset kind `other` (allow-list in `worker/src/assets.ts`, mirrored in `ASSET_LIMITS`): documents only, never HTML/SVG/scripts. Library files render as a same-origin `download` link (original filename); URLs open in a new tab.
- **Action button blocks are edited in place** like callouts: the editor renders the same `ButtonFrame` as Preview (a `<div>` while editing, a real `<button>` in Preview) with the icon picker (`CategoryIconPicker bare`), label and description typed on the button, and color swatches below. What the button does is wired in the hotspot Actions tab (its card warns until it has actions).
- **Callout blocks** have no separate form: the editor renders the same `CalloutFrame` / `CalloutBadge` as Preview and edits title / text inline, so what you edit is what Preview shows. `tone` is the color preset (new blocks: `neutral`); `icon` is an optional CATEGORY_ICONS name and falls back to the tone's default icon (`CALLOUT_TONES`).
- **Iframe blocks** embed https:// only (`parseIframeUrl`), with `IFRAME_BLOCK_SANDBOX` (scripts / forms / popups, **no** `allow-same-origin`) and a clamped height. Embedding can be refused by the target site and the browser cannot detect that, so an “Open in new tab” link under the frame is available as an opt-in (`showOpenLink`, off by default and when missing).
- **Action button blocks** store icon, label, optional italic description, a color preset (`BUTTON_BLOCK_COLORS`; new blocks default to `neutral`, blocks saved without `color` keep the old accent look), a synthetic graph owner (`−5000…−9999`), and an action graph. Preview interpolates label and description. They appear as first-class canvas lanes after hotspot click lanes (so fence Y for hotspots does not shift). Same allow-list as custom menu buttons (Open Modal only with a scene dialog). Remint `ownerId` when duplicating a hotspot or spawning from a template; keep it on scene load.

## Persistence and IO

- **DB-backed editor, explicit save.** The editor loads `projects.editor_data` + `scenes` + `assets` before mounting and saves on Save / Ctrl+S (no autosave yet; same path can be debounced later). No localStorage/IndexedDB. Dirty means the canonical fingerprint changed. Do not retake the baseline to hide a write, and do not persist a scene switch.
- **`hydrateProject` resets every module-level editor store that outlives the loader**: undo history, the action-fences store (it is seeded lazily from the scene per scope, so stale entries would shadow the loaded fences and be re-saved), and the subject cache. Add new session stores that hold authored data to that list. Publish asks `hasUnsavedChanges()` (synchronous fingerprint) rather than the debounced `dirty` flag, so an edit made a moment before clicking Publish is saved first.
- **Inactive scenes are normalized at load.** `hydrateProject` round-trips every non-active scene through the live stores (`hydrateLiveStores` + `snapshotCurrentIntoScene`) before the dirty baseline, so a scene switch never fills in defaults and marks an older project unsaved.
- **Georeference apply asks when the fit is questionable.** `buildGeoReference` returns `warnings` (RMS over 5% of the span between map points; three map points nearly in a line). Apply then needs an explicit "Apply anyway". The fit itself is never blocked.
- **The map and engine fail visibly.** `components/ui/map.tsx` shows "The map could not be loaded" with Try again when the style fetch fails or `load` does not arrive in 25 s (tile errors are ignored). A failing image overlay is skipped with one toast instead of aborting the whole overlay sync. The PlayCanvas hook disposes its controllers when unmounted or failing mid-init, shows the engine banner on WebGL context loss and redraws on restore, and frames the default box when a model reports non-finite bounds.
- **Save conflicts can be resolved in place.** The "Saved elsewhere" status opens a menu: download this editor's version (`downloadProjectBackup`, the serialized Save payload), keep mine (`overwriteSavedProject`: adopt the newest revision and save over it, after a confirm), or reload. Still no merge.
- **Scene delete states its impact and can be undone** (`lib/editor/state/scene-delete.ts`): the confirm lists hotspot count, the new primary (first scene in list order, not the open one), Go To Scene nodes that point at it, and georeferences it invalidates. Go To Scene nodes are left as they are (they show "Target scene no longer exists"). Undo (toast, scope `scenes`) puts the scene back at its index and restores primary + georeferences; its media is kept through the asset sweep while Undo is possible.
- **Scene-scoped forms do not author on sync.** Settings, environment, effects, and geo forms catch up to the hydrated store in the same render as the scene change (`useSceneFormReset`) and ignore that `watch` notification. A later effect reset can overwrite the incoming scene. User edits and the explicit Reset action still write the store.
- **`scenes.data` is the editor `Scene`**, minus lifted columns, plus `schemaVersion`. Action graphs stay where the editor owns them (per hotspot, scene start / legend, menu and action buttons); do not flatten them into scene-level `actions` / `nodes` lists. Bump `EDITOR_SCHEMA_VERSION` and migrate in `hydrate.ts` when the shape changes; Zod rejects malformed rows with a readable error.
- **One transactional save RPC** (`save_editor_project`, `SECURITY INVOKER`, called through the Data API). Per-scene PostgREST calls would not be atomic. Optimistic concurrency: `projects.editor_revision` must match or the save fails with `revision_conflict`; the user reloads (no merge).
- **Scene ids are uuids** generated in the browser so the editor id is the row id (Go To Scene nodes reference them). Slugs are assigned on first save and never change. Hotspot ids stay numeric per scene.
- **Project-level media library.** Every imported image / model is an `assets` row; authored fields keep strings and reference it as `asset:<uuid>` (URLs and `{{tokens}}` still work). Subjects use `model.subjectAssetId`. Resolve with `resolveAssetSrc`; missing assets render a placeholder. Do not add new data-URL fields.
- **Assets belong to the project, not a scene.** `assets.scene_id` is informational (no FK, no cascade). Uploads are deduped per project by `sha256`. Deleting a referenced asset is blocked in the library (`collectAssetRefs`). `POST /storage/projects/:id/assets/gc` deletes ready rows the saved project does not reference. The editor runs it on open (before the library query) and after a successful save. Rows younger than 15 minutes are never swept (pending: the presigned PUT may be in flight; ready: uploaded but not saved yet, here or in another tab), so an abandoned upload is cleaned up by a later sweep. The save-time sweep also sends a `keep` list (`liveAssetKeepIds`: everything the live editor references plus assets in undo/redo history entries, `HistoryEntry.assetIds`), so an asset applied while the save was in flight, or one Undo can restore, survives. `keep` can only protect more. The sweep returns the deleted ids and the client drops them from `useAssetsStore`. Deleting one asset (`DELETE .../assets/:id`) is refused with 409 while the saved draft references it, not just the live editor (the library's own "in use" check only sees live state): save first, then delete. Referenced assets stay. Project cover thumbnails are not asset rows and are not part of this sweep.
- **Subjects** load locally first, then upload in the background; Save waits for pending uploads. `scene-subject-cache` keeps the in-session blob per scene and fetches subject assets once per session. Import is a window event (`editor:import-subject`), not a direct engine call from the file picker.
- **Subject loads are cancellable.** `model-manager` keeps a load sequence: a newer load, `unloadCurrent`, `loadDefault`, or `cancelPendingLoads` (geo scene switch) makes every in-flight load stale, and a stale load discards its result (releases the asset / texture, no mount, no meta write, no toast). A user import is bound to the scene that was active when it started: it is dropped if the scene changes or a newer import begins, and its cache entry and asset upload use that captured scene id. `onSceneSwitched` in `use-playcanvas-editor.ts` only lets the newest switch finish (`sceneSwitchSeq`), clears `loadedPlayCanvasSceneId` while the viewport is empty, and after engine init replays a scene switch that happened during the first load (the listener is registered late).
- **Subject import is gated at one choke point** (`importSubjectFile`): not while in Preview or in a georeference alignment; GLB up to 150 MB and images up to 25 MB (the library limits, mirrored in `ASSET_LIMITS` and `worker/src/assets.ts`), images up to 8192 px on the longest side (one GPU texture). Streaming the local-dev upload keeps a 150 MB model out of Worker memory. After a replace, an aligned georeference is marked invalid (its control points were in the old subject's space) and the author is told that hotspots and the saved Reset view keep their old positions.
- **3D subject height** (`model.offsetY`, model scenes only) lifts the subject root on Y in scene units. Import normalizes the mesh so its base sits on Y = 0; the slider minimum is 0, so the subject cannot be moved below the ground. Reset Transform clears it. Older saves omit the field and load as 0.
- **Camera pose previews** (`CameraResetPosition.previewUrl`) stay small inline JPEG data URLs: generated, ~20 KB, editor-only.
- Existing `exportHotspots()` is a hotspot-list dump, not a project format. Do not treat it as the save system.

## File storage (R2)

- **Worker is the storage gateway**, not a Neon Function. It already holds the user JWT, so authorization is "can this user read the project row under RLS". No R2 credentials or bucket URLs reach the browser except a short-lived presigned URL.
- **Uploads are presigned S3 `PUT`s** (5 min, `content-type` signed) straight to R2, so file bytes never pass through Next or the Worker. A separate **commit** step validates the object (`head`: type, size) before the DB references it; rejected uploads are deleted.
- **Reads are streamed by the Worker** through the `ASSETS` binding at `/gateway/files/<key>` (private bucket, session cookie works with plain `<img>`). No public bucket or `r2.dev` URL.
- **DB columns hold R2 keys, never URLs** (e.g. `projects.thumbnail_r2_key`). Keys start with `orgs/{orgId}/projects/{projectId}/` and the Worker checks that prefix against the project row.
- **Asset keys** are `assets/{assetId}.{ext}` under the project prefix: no scene folder and no filename, so reuse across scenes and renames never move bytes.
- **Files are served with `nosniff` + a sandbox CSP**, since they come from the app origin and the library accepts SVG.
- **Unique key per upload** (`thumbnails/{uuid}.webp`, not a fixed `cover.webp`) so responses can be cached `immutable` and the old object is deleted only after the swap commits.
- **Client normalizes images** (16:9 center crop, ≤ 1920×1080 WebP) so stored thumbnails stay small and uniform.
- **Local-first dev storage.** Without R2 S3 credentials the Worker accepts the upload itself (`/thumbnail/upload`, same auth/key/type/size checks) into the Miniflare bucket, so storage works offline. The remote binding is opt-in (`npm run dev:api:r2`) for testing real presigned uploads; plain `dev:api` must not require a Cloudflare login. Production must have the S3 credentials set so bytes bypass the Worker.

## Publishing

- **Immutable server-built snapshots.** `publish_project_version` builds the snapshot in SQL from the saved rows after an `expected_revision` check; the browser never sends snapshot JSON. The future viewer reads only `project_versions` (`status = 'published'`), never `projects` / `scenes`.
- **No Data API writes to `project_versions`.** Migration 0007 revokes INSERT / UPDATE / DELETE from `authenticated` (and `anonymous`) and leaves a select-only policy. Only the SECURITY DEFINER RPCs write; each checks `is_org_member` itself and uses `current_user_id()` (never `auth.*`, see migration `0005`).
- **Retention is 5 versions per project, live included**, pruned on publish in the same transaction. The new snapshot and the version that was live are always kept, even when that live version is older than newer archived ones; other slots go to the newest version numbers. Unpublish archives and never prunes. Republish (`republish_project_version`) makes an archived snapshot live and does not change the editor draft or mint a version. Any org member may publish (same access as `projects`).
- **Assets referenced by the draft or any retained version are kept.** The Worker GC adds `project_versions.asset_ids` to its keep set; asset delete is refused with 409 while a retained version references the file. Pruning only drops the version row, so GC reclaims files on a later sweep.
- **Password hash lives in `project_publish_secrets`** (RLS on, no policies or grants), not on `projects`, because `projects` is fully readable by org members. `projects.publish_password_protected` is the readable flag.
- **Publish saves first.** A dirty draft is saved, then the fresh revision is published. Uploads in flight block publishing, like Save.

## Secure API proxy (v2, not built)

Planned so HTTP Request / Subscribe nodes can call authenticated customer APIs. Today they are anonymous and client-side (see "HTTP Request / Subscribe fetches are bounded and anonymous"), so a credential typed into a node is visible to anyone who opens a published tour. These are the constraints for building it; nothing here exists yet.

- **Why a proxy:** a secret must never reach the browser, so authenticated calls in a published tour have to go through the Worker (`/fn` path or a dedicated route). Client-side headers stay the editor/Preview-only escape hatch.
- **Cost is the main risk, not the secret store.** Naive per-viewer proxying scales as nodes × viewers × polls (one Subscribe at 5 s is about 17k requests/day per viewer). The design must keep cost independent of viewer count:
  - **Coalesce polls server-side.** One upstream call per project + node + interval, shared by all viewers (Durable Object or Cache API entry keyed by project/node). Viewers read the cached payload.
  - **Neon is not in the hot path.** Secrets are stored encrypted (RLS-protected table like `project_publish_secrets`, no Data API read), decrypted in the Worker and cached in isolate memory / KV with a short TTL. The DB is hit on secret changes only.
  - **Minimum proxied interval** (about 15–30 s, stricter than the 5 s anonymous floor), polling paused while the tab is hidden, and per-plan monthly request quotas with a clear error when exceeded.
  - **Proxy only requests that use a secret.** Public endpoints stay client-side and cost nothing.
- **Authoring:** secrets are named, org/project-scoped entries (Settings → Organization → API secrets, currently "Coming soon"). Nodes reference a secret by name, never its value; the value is write-only after creation. The Worker injects it into the configured header at request time.
- **Safety:** the proxy keeps the existing bounds (timeout, response cap, no session cookie) and must block SSRF (private / loopback / metadata IP ranges, redirects re-checked) and restrict the secret to its configured host.
- **Pricing:** treat it as a paid-tier feature so the request volume is priced in.
- **No-cost alternative to keep documenting:** Post Message receive. The host portal does its own authenticated fetch and pushes `{ event, data }` into the viewer, so credentials never reach this platform. Prefer it for enterprise embeds; the proxy is the convenience option for standalone links.
- **Depends on:** the public viewer route and a Neon Function URL / Worker route for the proxy (both listed under Planned in `features.md`).

## Viewer analytics (planned, not built)

Simple analytics for published projects, built after the viewer exists. Nothing here is implemented; `/projects/[id]` Analytics still shows seeded sample data.

- **Cloudflare Workers Analytics Engine (WAE), not Postgres and not a separate NoSQL store.** Events are columnar, written from the Worker with `writeDataPoint` (non-blocking, no DB connection), and read through the WAE SQL API. Postgres is bad at event aggregation and every event would be a billed write; a NoSQL store needs its own aggregation and a sync pipeline. Neon is not involved at write time.
- **Flow:** the published viewer batches events and sends them with `navigator.sendBeacon` (every ~10 s and on `pagehide`) to a Worker `/analytics/collect` route, which validates that the project is published, rate-limits, filters bots, and writes data points. Batching keeps Worker invocations about 10–50× lower than one request per event.
- **Only the published viewer emits events.** Never from the editor or Preview.
- **Event set stays small:** `session_start` (referrer / embed host, device class, country from `cf`), `scene_view`, `hotspot_open`, `action_button`, `dwell` (seconds, at session end). Do not add high-frequency events (pointer, per-frame); data point count, and cost, would grow about 10×.
- **Data point layout:** index = `projectId` (adaptive sampling is per index, so one busy project cannot crowd out the others; queries use `SUM(_sample_interval)`). Blobs: event type, scene id, hotspot id, country, device, embed host. Doubles: value (e.g. dwell seconds), published version number.
- **Privacy:** no cookies, no IP stored, random per-tab session id in `sessionStorage`. "Unique viewers" means unique sessions. Numbers are sampled and approximate under load; fine for views, top scenes and hotspots, not billing-grade.
- **Reads:** a Worker `/analytics/query` route checks org membership against the project row (same check as `/storage`), runs a fixed set of parameterized WAE SQL queries (never browser-supplied SQL), and caches results for a few minutes. It replaces the sample-data source in the Analytics tab.
- **Long retention:** a daily Worker cron rolls yesterday's counts into a small Postgres table (`project_analytics_daily`: one row per project per day, JSON counts), so long ranges are fast and survive a backend change. WAE's own retention is not stated on its pricing page; verify before promising clients a window.
- **Escape hatch:** if a client needs exact counts, funnels or session replay, add D1 (exact counts) or PostHog / Tinybird as a paid tier. Do not build it into v1.

### Cost estimate (v1)

Prices from Cloudflare's pricing pages (checked 2026-10-26). Workers Paid is $5/month base and includes 10M requests, 30M CPU ms, 10M WAE data points written and 1M WAE read queries. Overage: $0.30 per 1M requests, $0.02 per 1M CPU ms, $0.25 per 1M data points, $1.00 per 1M read queries. WAE is currently not billed at all, so the numbers below assume billing is switched on.

Assumptions: about 8 data points per session, about 3 collect requests per session (batched), about 2 ms CPU per collect request, and a negligible number of dashboard queries (far below 1M).

| Sessions / month | Data points | Collect requests | CPU ms | Overage | Total (with $5 base) |
| --- | --- | --- | --- | --- | --- |
| 10k | 80k | 30k | 60k | $0 | $5 |
| 100k | 800k | 300k | 600k | $0 | $5 |
| 1M | 8M | 3M | 6M | $0 | $5 |
| 10M | 80M | 30M | 60M | about $25 ($17.50 data points + $6 requests + $0.60 CPU) | about $30 |

- **The analytics endpoint is not the main Worker cost.** Each tour load also fetches the GLB, images and thumbnails through `/gateway/files/<key>`, which are Worker requests too: roughly 10–50 per load against 3 for analytics. Budget the viewer's traffic separately (at 1M sessions, about $0–12 of request overage). R2 egress is free; R2 storage and operations are billed separately.
- The estimate rests on the event assumptions above. More events per session scale data points linearly.

## Leaving and crashing the editor

- **Leave guard** (`use-leave-guard.ts`): `beforeunload` only covers tab close/reload. A capture-phase click listener asks before any same-origin link navigates away with unsaved changes, and once the project is dirty an extra same-URL history entry lets the Back button be asked too. Programmatic `router.push` is not intercepted. `hasUnsavedChanges()` flushes the 400 ms dirty debounce, so an edit made a moment ago still counts.
- **Editor error boundary** (`editor-error-boundary.tsx`) sits inside the loader, which owns the stores, so a render error keeps the project in memory and offers Save now / Download backup (serialized project JSON) / Try again.

## Undo / redo

- **Scoped snapshot history** (`lib/editor/history/`). `history-store.ts` holds one past/future stack per scope string (cap 100); entries are `{ label, undo, redo }` that write straight to the stores and never record themselves. `snapshot.ts` turns before/after JSON snapshots into an entry (`recordSnapshotChange` / `runSnapshotChange`, no-ops skipped) and `toastUndo` shows the Undo toast, which only undoes its own entry while it is still the latest.
- **Action canvas** uses scope = its fence scope key (`scene:<id>` or the spawn-click key). Snapshots hold the touched owners' graphs plus that scope's fences; fences restore membership only (`mergeFenceSnapshot`), so later geometry edits survive. Covered: delete node / connection / fence / multi-select, add, paste, connect. Not yet covered: node drags, field edits inside nodes, and row deletes inside nodes (header / event / field / case), which still confirm.
- **Shortcuts** are bound per canvas (`use-actions-shortcuts.ts`), not globally; the newest mounted canvas wins so a spawn-click modal over Scene Actions doesn't double-fire. Wire a new area's Ctrl+Z the same way against its own scope.
- **To make another area undoable:** pick a scope, capture the stores it touches before and after the mutation, and call `recordSnapshotChange` (add `toast` for destructive actions). Do not call `history.record` from inside `undo` / `redo`. Clear a scope when its writers go away (the spawn-click lane does this on close); `hydrateProject` clears everything.
- **Preview surface theming:** each styled Preview surface (legend, scene explorer, hotspot dialog, plus the portaled legend category menu) carries `editor-preview-surface`. CSS in `editor-theme.css` remaps `--editor-fg/muted/line/input-bg` inside it, so secondary text, icons, and hovers derive from the surface text color, and selection uses the accent. New surfaces: add the registry entry, the `--ps-*` alias, and the class. Portaled children need the class passed explicitly (see `CategorySelect.menuClassName`).
